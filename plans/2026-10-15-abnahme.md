## Limits and external evidence

Docker was not run. A full-planet run and production-relevant planet throughput
and disk measurements remain outstanding. Source and processing are
configurable; partitioned lookups, external sorting, worker RSS limits, and
finite update budgets constrain individual processing steps. A subsequent
documentation review found that the shared update geometry member cache lacks
an aggregate byte cap: the 64 MiB resolved-object bound applies per lookup,
not to total updater RAM. This is an explicit planet-production follow-up in
[TODO.md](TODO.md). Each update batch still performs a hardlink
copy, inventory check, exact recount, and synchronization proportional to the
whole generation. Automatic cleanup of old generations is not implemented.
These costs do not demonstrate planet-scale throughput.

Nested relations are not fully resolved recursively in the initial index.
Inline coordinates alone do not provide complete metadata for synthesized
member nodes. Therefore, this report does not claim general Overpass parity.
The public Tokyo parity attempt returned HTTP 406, so that network check remains
open. The reusable `npm run parity` command is available for later comparisons.
